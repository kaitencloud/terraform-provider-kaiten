# Kaiten Provider

The Kaiten provider manages [Kaiten](https://kaiten.sh) infrastructure through the Kaiten
Core API. It covers deployment zones: the regions and environments instances are deployed to.

## Authentication

The provider needs the base URL of a Kaiten Core API and an organization-scoped API token
(`ksh_...`). It resolves each one separately, from the first of these sources that sets it:

1. The `base_url` and `auth_token` arguments of the provider block.
2. The `KAITEN_BASE_URL` and `KAITEN_AUTH_TOKEN` environment variables.
3. The `base_url` and `auth_token` keys of the Kaiten CLI configuration file, `kaiten/config.yaml`
   under the user configuration directory (`~/.config` on Linux, `~/Library/Application Support`
   on macOS, `%AppData%` on Windows).

These are the variables and the file the [Kaiten CLI](https://github.com/kaitencloud/cli)
reads, so a machine where `kaiten` works needs no further setup. Keep the token out of
configuration where you can.

## Example Usage

```terraform
# Credentials are best left out of configuration: export KAITEN_BASE_URL and
# KAITEN_AUTH_TOKEN, or log in with the Kaiten CLI, and leave the block empty.
provider "kaiten" {}
```

With explicit settings:

```terraform
variable "kaiten_auth_token" {
  type      = string
  sensitive = true
}

provider "kaiten" {
  base_url   = "https://kaiten.example.com/api"
  auth_token = var.kaiten_auth_token
}
```

### Optional

- `auth_token` (String, Sensitive) Organization-scoped API token (`ksh_...`). May also be set via the `KAITEN_AUTH_TOKEN` environment variable, or the `auth_token` key of the Kaiten CLI configuration file.
- `base_url` (String) Base URL of the Kaiten Core API, including its path prefix, e.g. `https://kaiten.example.com/api`. May also be set via the `KAITEN_BASE_URL` environment variable, or the `base_url` key of the Kaiten CLI configuration file.
